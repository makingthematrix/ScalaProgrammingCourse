Next on the agenda: what is Scala? Scala is a programming language on the JVM platform, similar to Java and Kotlin. Its creator is Martin Odersky, who first worked on generics in Java and then went on to develop his own programming language. Scala features even more generics, meaning a more complex type system. Compared to Java and Kotlin, Scala is much more oriented towards functional programming and complex type systems.

Martin Odersky works at EPFL, the École Polytechnique Fédérale de Lausanne in Lausanne, Switzerland, and that's where Scala is mainly developed as a language and compiler. Scala Center, which coordinates and strengthens the global Scala community, is also based there.

Timeline: Martin started working on Scala around 2003. Scala 1.0 was a very private project; it wasn't until Scala 2 in 2006 that things started happening outside of EPFL. For a long time, Scala was a small, niche language developed somewhat on the sidelines. It blew up a bit in around 2013 when Twitter picked it up for its backend.

The oldest version of Scala 2 that you might see in action are most often version 2.11, which is maintained as a legacy on many Spark projects. If someone is working on Android, like I used to, it's 2.11. 2.12 is similar, but there's a big split in the JVM itself between version 2.11 and 2.12, because 2.11 runs on Java 7, while 2.12 uses newer constructs from Java 8. The syntax is the same, but what happens underneath in the bytecode is quite different. Scala 2.12 was followed with 2.13 that received many fixes and performance improvements. It's still maintained and there are no plans to stop it, but all new cool stuff is now developed in Scala 3.0. Scala 3.0 was released in 2021, with a syntax that is already somewhat different from Scala 2, although some backward compatibility is maintained. This year, Scala 3.9 was released, and this is also the year when the compiler team decided that it's time to slowly break with this backward compatibility with Scala 2.

So now the question is, why Scala, why would you use it at all? First of all, Scala exists in the JVM system, so we have some interoperability. These three languages are compiled to the same bytecode, which means they can work together. This is a great advantage for Scala because we don't have to reinvent all the tools. If we don't have something in Scala, we can take it from Java, mainly from Java. However, the connection between Scala and Java is simpler than between Scala and Kotlin, due to some decision differences in how these languages are being developed.

If we want to use Kotlin, it's best to have a thin layer of Java in the middle where Scala calls Java, and Java calls Kotlin. But this only makes sense for really large projects. 

Being on JVM, Scala allows you to write code that is safer and more functional, while still being able to use the entire huge Java ecosystem. On the other hand, there are languages that, like Scala, have certain elements of functional programming, such as Haskell and Rust - but they don't have access to such a big ecosystem. Kotlin, by the way, has a library called Arrow that provides many solutions for Kotlin that are more functional programming than standard Kotlin. And Swift is also somewhere on this spectrum as well, perhaps a bit less than Scala, but somewhere around Kotlin. So we can say that these languages use different concepts to varying degrees related to functional programming, which makes the code perhaps a bit more abstract, definitely safer, and more can be said about the programming code itself at the level of such metadata as the type system. And this is another thing we want to return to, that generally I would like you not to necessarily think that you are learning Scala just to graduate and go and program in Scala.

 However, it is certainly worth learning Scala because, being in both worlds at the same time, Scala is, I think, a great place where you can experiment with new programming techniques. Scala is generally a bit of a testing ground for new concepts, both for Kotlin, Java, and to some extent Rust. They took various concepts from Scala that were first tested on live people sometimes, and then, once they were tested and properly done, they entered wider use. Recently in Java, we have new ideas related to pattern matching that mimic what we have in Scala.

One thing only - if you want to use other languages, I would like to motivate you to use statically typed languages. The type system is a way to better understand the code. It is a way to have minimal documentation right away, because every method, every variable, every field, every class is exactly described: what it can take, what it does, and in the case of functions, what their result is. When you refactor, if you change something in a method or a class, the compiler can immediately tell you what else needs to be changed in the entire program, which is very useful when the program is medium to large. All this is well described by types, and programs can catch a lot of errors at the compiler level, so these errors won't reach runtime and explode in the user's face, which can be very unpleasant.

Types are your friends. Especially now, when AI is doing more and more of our coding, a strict, mature type system, helps a lot. AN AI agent may generate code, try to compile it, and when it fails, the compiler gives back actually useful error messages, enabling the AI agent to fix the issue.
